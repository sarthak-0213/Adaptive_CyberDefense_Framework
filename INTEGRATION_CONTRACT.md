## 1. Architectural Overview & Topology

ACDF operates as the **Security Gateway & Reverse Proxy Perimeter** in front of SecureShop. Client traffic, external integrations, and potential attackers interact with ACDF, which applies deep packet inspection, decoy traps, and dynamic Moving Target Defense (MTD) before proxying legitimate requests upstream to SecureShop.

```text
[ Client / Attacker / Browser ]
             │
             ▼
  ┌────────────────────────────────────────────────────────┐
  │   Adaptive Cyber Defense Framework (ACDF :8000)        │
  │                                                        │
  │  • Threat Blocker Middleware (IP Denylist Check)       │
  │  • WAF Engine (SQLi, XSS, Path Traversal Detection)    │
  │  • Honeypot & Decoy Trap Interception                  │
  │  • Moving Target Defense (MTD Route Shuffler)          │
  │  • Adaptive Risk & Telemetry Engine                    │
  └──────────────────────────┬─────────────────────────────┘
                             │ Forwarded via Internal Reverse Proxy
                             ▼
  ┌────────────────────────────────────────────────────────┐
  │   SecureShop E-Commerce Backend (:8001)                │
  │                                                        │
  │  • Catalog API (/api/products)                         │
  │  • Authentication API (/api/auth/login, register)      │
  │  • Orders API (/api/orders)                            │
  │  • Protected Admin Services                            │
  └────────────────────────────────────────────────────────┘
```

## 3. Gateway URLs & Routing Contracts

All external public and client traffic to SecureShop **MUST** traverse the ACDF Gateway perimeter:

| Public Gateway URI | Method | Upstream SecureShop Target | Security Controls Applied |
| :--- | :---: | :--- | :--- |
| `http://127.0.0.1:8000/gateway/api/products` | `GET` | `http://127.0.0.1:8001/api/products` | WAF Query Param Inspection, IP Block Check |
| `http://127.0.0.1:8000/gateway/api/auth/login` | `POST` | `http://127.0.0.1:8001/api/auth/login` | WAF Body Inspection, Brute-Force Rate Limiting |
| `http://127.0.0.1:8000/gateway/api/auth/register` | `POST` | `http://127.0.0.1:8001/api/auth/register` | WAF Body Inspection, Malicious Payload Check |
| `http://127.0.0.1:8000/gateway/api/orders` | `POST` | `http://127.0.0.1:8001/api/orders` | JWT Header Preservation, SQLi/XSS Inspection |
| `http://127.0.0.1:8000/gateway/api/admin/debug` | `ANY` | *(Decoy Trap — No Upstream)* | Honeypot Trigger (+40 Risk Score, Fake 404) |
| `http://127.0.0.1:8000/api/v1/d/{dynamic_token}` | `GET` | Upstream `/api/admin/dashboard` | MTD Protected Dynamic Alias (200 OK / 410 Gone) |

### Header Handling:
- Client IP resolution utilizes `X-Forwarded-For`. If missing, falls back to `request.client.host`.
- Authorization tokens (`Bearer <JWT>`) are transparently forwarded to SecureShop.
- Hop-by-hop headers (`host`, `content-length`, `connection`) are sanitized and regenerated by the gateway.

## 4. Telemetry Event Ingestion Contract

In addition to inline gateway traffic inspection, SecureShop can emit asynchronous security telemetry events directly into ACDF's Adaptive Risk Engine.

### Ingestion Endpoint
`POST http://127.0.0.1:8000/api/v1/security/events`  
**Content-Type:** `application/json`

### Event Schema
```json
{
  "ip_address": "192.168.1.105",
  "event_type": "failed_login",
  "source": "secureshop_auth",
  "metadata": {
    "attempted_email": "target_user@example.com",
    "user_agent": "Mozilla/5.0 ...",
    "reason": "invalid_credentials"
  }
}
```

#### Field Specifications:
- `ip_address` *(string, required)*: The IPv4 or IPv6 address of the originating client.
- `event_type` *(string, required)*: Type identifier. Supported standard types:
  - `failed_login`: Increment single authentication failure count (+10 base score).
  - `rapid_login_attempt`: Repeated authentication failures within sliding window (+25 base score).
  - `sqli_attempt`: SQL injection payload attempt (+30 base score).
  - `xss_attempt`: Cross-Site Scripting signature detected (+25 base score).
  - `honeypot_hit`: Client accessed decoy honeypot route (+40 base score).
  - `direct_protected_path`: Unauthorized attempt to bypass MTD alias (+35 base score).
- `source` *(string, required)*: Reporting subsystem (e.g., `secureshop_auth`, `secureshop_checkout`, `gateway_waf`).
- `metadata` *(object, optional)*: Key-value dictionary containing contextual audit details.

### Response Schema (`HTTP 201 Created`)
```json
{
  "status": "recorded",
  "ip_address": "192.168.1.105",
  "current_score": 59.99,
  "threat_level": "HIGH",
  "active_block": true
}
```

## 5. Moving Target Defense (MTD) Contract

Sensitive upstream endpoints (specifically administrative consoles and internal diagnostics) are protected using dynamic route polymorphism.

1. **Direct Path Concealment:**  
   Direct access to `http://127.0.0.1:8000/gateway/api/admin/dashboard` returns **HTTP 404 Not Found** and logs an unauthorized path discovery attempt.
2. **Dynamic Alias Consumption:**  
   Authorized administrators query `GET /api/v1/mtd/status` to obtain the currently active route token:
   ```json
   {
     "protected_paths": ["/gateway/api/admin/dashboard"],
     "active_aliases": {
       "/gateway/api/admin/dashboard": "/api/v1/d/6bddbbda"
     }
   }
   ```
3. **Rotation & Invalidation Lifecycle:**  
   - Shuffling can occur periodically or via `POST /api/v1/mtd/shuffle`.
   - When a rotation occurs, the previous alias is retired and returns **HTTP 410 Gone**.
   - The newly generated alias returns **HTTP 200 OK** and proxies to the upstream dashboard.

## 6. Adaptive Response & Autonomous IP Blocking

1. **Thresholds:**
   - **LOW:** Threat Score $0.0 - 19.9$ (Normal monitoring).
   - **MEDIUM:** Threat Score $20.0 - 49.9$ (Elevated scrutiny).
   - **HIGH:** Threat Score $50.0 - 79.9$ (**Autonomous IP Block Triggered**).
   - **CRITICAL:** Threat Score $\ge 80.0$ (**Immediate Perimeter Block Triggered**).
2. **Enforcement:**
   - When an IP is blocked, an active record is added to the `ThreatBlock` repository.
   - All subsequent HTTP verbs and paths from that IP receive **HTTP 403 Forbidden**.
3. **Remediation & Recovery:**
   - SOC Analysts view blocked entities at `GET /api/v1/security/blocks`.
   - Authorized unblock requests can be submitted via:
     `POST /api/v1/security/blocks/{ip}/unblock` or `DELETE /api/v1/security/blocks/{ip}`.
   - Once unblocked, traffic is immediately restored with zero application restart required.

| Gate | Name | Action | Expected Criteria | Status |
| :---: | :--- | :--- | :--- | :---: |
| **G1** | Normal Activity | Request catalog & login with valid credentials | HTTP 200 OK, zero threat score accumulation | **PASS** |

| **G7** | Recovery | SOC Admin issues unblock API command | Block status removed; normal access restored (200) | **PASS** |
| **G8** | Regression | Full checkout workflow (catalog, auth, orders) | 100% operational throughput through gateway | **PASS** |
